# 多 Provider DNS 查询

## 用户故事

- 作为一个排查"这域名到底解到哪儿了"的人，我希望一条命令同时拿到多个公共 DNS（Cloudflare、Google、Quad9、AliDNS……）的解析结果并排对比，而不是挨个 `dig @` 敲一遍。
- 作为一个怀疑自己被 DNS 投毒 / 劫持的人，我希望同一条域名查询在多个上游 Provider 之间交叉验证，谁和谁不一致一眼看出来。
- 作为一个想换 DoH / DoT 上游的人，我希望先测一遍候选 Provider 的连通性和延迟，再决定把谁写进配置，而不是配完才发现连不上。
- 作为一个想知道"这域名归哪个 NS 管"的人，我希望查完解析结果后顺手看到这域名的真实 zone 和权威 NS 服务器列表，不用再单独跑一次 `dig NS`。

## 为什么需要

公共 DNS 之间结果不一致是常态——CDN 调度、地理策略、缓存错位都会让同一个域名在不同上游解到不同 IP。只问一个 Provider 等于只听了故事的一面。另外，想从普通 UDP DNS 迁到 DoH / DoT 提升隐私和稳定性，又怕新上游在自己网络环境里时断时续，没个轻量手段先验一下连通性，贸然切换很容易踩坑。

## 怎么解决

终端里敲一条命令，带上域名，GeoPrism 并行向配置好的多个 DNS Provider 发起查询，把每家的解析结果归并成一张表摆出来。Provider 来自本地 TOML 配置（首次启动自动写一份默认模板，包含主流公共 DNS），想加哪家加哪家、想指定只用某几家就传名字过滤。想验上游是否可达，单独一条命令挨个测连通性。域名查询完之后，自动追加这域名的 NS 服务器信息——包括自动向上探测真实 zone（用户查的可能是子域名，zone apex 要往父域找）。

## 边界

- 只做查询，不做投毒 / 劫持检测的主动判定——结果摆出来由人判断，不替用户下"被劫持了"的结论。
- 不管 DNS 缓存的写入策略，只读式地查；不上游缓存刷新或预热。
- Provider 连通性测试只告诉你"通不通、多久"，不报告具体网络层的丢包率、TLS 握手细节等诊断指标——那是专门网络工具的事。
- 不提供 Web UI / 后台常驻服务，就是个跑完即退出的 CLI。
- 配置文件只读 `providers.toml` 这一份；旧的 `providers.json` 不读也不自动迁移，检测到会提示手动迁移。
