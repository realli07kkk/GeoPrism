# 离线 IP / CIDR 查询

## 用户故事

- 作为一个经常在飞机 / 弱网环境下排查 IP 归属的人，我希望 IP 查询完全不依赖在线服务，本地就能秒出这个 IP 属于哪个国家 / ASN / 网段，而不是开浏览器等一个在线查询页面加载。
- 作为一个拿到一批日志、想看"这一片 IP 大概都归谁"的人，我希望直接丢一个 CIDR 进去，拿到所有和它相交的网段记录，而不是挨个 IP 查一遍再自己聚合。
- 作为一个既想离线查又舍不得 ipinfo 精度的用户，我希望本地离线库命不中时自动 fallback 到 ipinfo 在线 API 查一次，查到的结果还能回写进本地库——下一次同样的 IP 就直接离线命中了。
- 作为一个关心数据可信度的人，我希望每条查询结果都标明它来自离线库还是在线 API，而不是混在一起让我猜。

## 为什么需要

IP 归属查询是排查和归档日志时的常驻需求，但绝大多数在线服务要么限速要么要联网。把整张 IP 库（如 ipinfo Lite）一次性导入本地，查询就退化成纯本地操作，断网、批量、脚本化都没压力。但完全离线也有代价——离线库有更新周期，冷门网段可能查不到；这时候一个"在线兜底 + 结果回写"的机制就能让本地库越用越全，又不牺牲离线查询的主路径速度。

## 怎么解决

提供一条命令把外部 CSV 格式的 IP 库导入本地存储，导入完之后单 IP / CIDR 查询都走本地。单 IP 查询优先走本地离线库；本地没有但配置了 ipinfo token，就 fallback 到在线 API 查一次并异步回写本地库，让下次同 IP 直接命中。CIDR 查询直接对本地库做"所有相交网段"检索，一次性把这片 IP 的归属全摆出来；只有本地完全没命中时，才拿 CIDR 基地址回退到单 IP 查询逻辑。每条结果都带一个来源标记（`ipdb` / `ipinfo`），让人一眼分清可信度。数据源优先级可在配置里切换（默认离线优先，也可设成在线优先）。

## 边界

- 只查归属信息（国家 / ASN / 网段描述这类），不做威胁情报、恶意 IP 判定、端口扫描——那不是这个工具的职责。
- 离线库本身不自动更新；需要人手动重新跑导入命令刷新，工具不内置定时拉取。
- ipinfo 在线 fallback 依赖用户自己配置的 token；token 为空时这层兜底整个关闭，只报错提示。
- 同一 IP 的在线查询在一次运行内会去重（多次出现只调一次 API），但跨进程运行不共享缓存。
- 数据源优先级配置只影响单 IP 查询的主路径；CIDR 查询固定走"离线优先、未命中才回退"，不受这个开关控制。
- 不提供库的可视化浏览界面；要翻整库内容请直接看源 CSV。
